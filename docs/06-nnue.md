# 06. NNUE

Файл: [`engine/src/nnue.rs`](../engine/src/nnue.rs)
Веса: [`engine/nnue_weights.bin`](../engine/nnue_weights.bin) (37 510 байт)

NNUE (Efficiently Updatable Neural Network) — подход из компьютерных шахмат:
небольшая полносвязная сеть, работающая на целочисленной арифметике, вызываемая
миллионы раз в секунду прямо в листьях дерева поиска.

## Особенность реализации в этом проекте

Классический NNUE в шахматах инкрементально обновляет первый слой при каждом
ходе — отсюда «efficiently updatable». **Здесь инкрементального обновления нет**:
`evaluate()` каждый раз собирает вектор признаков с нуля и считает все слои
полностью.

Это осознанный компромисс. Вход всего 40–58 значений (в шахматах — десятки тысяч
разреженных признаков), поэтому полный прямой проход дёшев, а код остаётся
простым. Сеть остаётся NNUE по архитектуре и квантованию, но не по механизму
обновления.

## Архитектура

Поддерживаются две конфигурации входа и две глубины сети:

```
40 входов  → Linear(h1) → CReLU → Linear(h2) → CReLU → Linear(1)
58 входов  → Linear(h1) → CReLU → Linear(h2) → CReLU → Linear(h3) → CReLU → Linear(1)
```

Ограничения размеров ([`nnue.rs:48-50`](../engine/src/nnue.rs#L48-L50)):

```rust
const MAX_HIDDEN1: usize = 512;
const MAX_HIDDEN2: usize = 64;
const MAX_HIDDEN3: usize = 64;
```

По отчётам боевая конфигурация — `40 → 256 → 32 → 1`. Эксперименты с `512×64`
дали меньший val_loss, но играли **слабее** — см. [12-results.md](12-results.md).

## Квантование

```rust
const SCALE: i32 = 64;
```

Все веса и активации — `i16` с фиксированной точкой, знаменатель 64. Активация —
**CReLU** (clipped ReLU), то есть ReLU с потолком:

```rust
hidden1_buf[j] = (acc / SCALE).clamp(0, SCALE);
```

Ограничение сверху нужно, чтобы промежуточные значения не переполняли `i32` при
накоплении и чтобы диапазон активаций был предсказуем для квантования.

Выход сети делится на 64 ещё раз в [`Searcher::eval()`](../engine/src/search.rs#L168):

```rust
let base = nnue.evaluate(board) / 64;
```

Именно поэтому константы поиска (`ASP_DELTA = 20`, `RFP_MARGIN = 70`)
откалиброваны под другую шкалу, чем веса HCE.

## Бинарный формат

[`load()`, nnue.rs:70](../engine/src/nnue.rs#L70)

Формат определяется автоматически по первому `u16`:

| Первое значение | Трактовка |
|-----------------|-----------|
| `< 128` | новый формат — это `input_size` (40, 52 или 58) |
| `>= 128` | старый формат — это `hidden1` (256 или 512), `input_size` подразумевается 40 |

Эвристика работает потому, что размер входа всегда меньше 128, а размер первого
скрытого слоя всегда больше.

### Новый формат

```
[input_size: u16][hidden1: u16][hidden2: u16][hidden3: u16]   ← 8 байт
fc1_weight: i16 × (hidden1 × input_size)
fc1_bias:   i16 × hidden1
fc2_weight: i16 × (hidden2 × hidden1)
fc2_bias:   i16 × hidden2
if hidden3 > 0:
    fc3_weight: i16 × (hidden3 × hidden2)
    fc3_bias:   i16 × hidden3
    fc4_weight: i16 × hidden3
    fc4_bias:   i16 × 1
else:
    fc3_weight: i16 × hidden2
    fc3_bias:   i16 × 1
```

### Старый формат

```
[hidden1: u16][hidden2: u16]                                  ← 4 байта
далее как выше, input_size = 40, hidden3 = 0
```

Все значения — little-endian.

## Входные признаки

### Базовые 40

[`build_input_40`, nnue.rs:182](../engine/src/nnue.rs#L182)

| Индексы | Признак | Нормализация |
|---------|---------|--------------|
| 0–8 | лунки ходящего | `× 64 / 50` |
| 9–17 | лунки соперника | `× 64 / 50` |
| 18 | қазан ходящего | `× 64 / 82` |
| 19 | қазан соперника | `× 64 / 82` |
| 20–29 | тұздық ходящего, one-hot (индекс 29 = «нет») | `64` |
| 30–39 | тұздық соперника, one-hot (индекс 39 = «нет») | `64` |

Признаки строятся **относительно ходящей стороны**, а не абсолютно. Это
удваивает эффективный объём обучающих данных: одна позиция учит сеть и за белых,
и за чёрных.

Делитель 50 для лунок — эмпирический потолок: в лунке редко бывает больше 50
камней, но формально ограничения нет, и при 60 камнях признак выйдет за
пределы `SCALE`.

### Расширение до 58

[`build_input_58`, nnue.rs:209](../engine/src/nnue.rs#L209)

18 стратегических признаков, кодирующих то, что HCE считает явно:

| Индекс | Признак | Нормализация |
|--------|---------|--------------|
| 40, 41 | всего камней у меня / у соперника | `/ 81` |
| 42, 43 | активных (непустых) лунок | `/ 9` |
| 44, 45 | тяжёлых лунок (≥12 камней) | `/ 9` |
| 46, 47 | слабых лунок (1–2 камня) | `/ 9` |
| 48, 49 | камней в правых лунках (7–9) | `/ 81` |
| 50 | фаза партии (всего камней на доске) | `/ 162` |
| 51 | разница қазанов | `/ 82`, clamp |
| 52, 53 | угрозы тұздық (лунки с 2 камнями) | `/ 8` |
| 54, 55 | starvation pressure, квадратичная | `max(0, 20−камни)² / 400` |
| 56, 57 | цели захвата (лунки с чётным числом камней) | `/ 9` |

Признаки 52–57 добавлялись в последнем крупном эксперименте
([`NNUE_EXPERIMENTS.md`](../NNUE_EXPERIMENTS.md)). Прироста силы он не дал —
подробности в [12-results.md](12-results.md).

Промежуточный вариант с 52 входами поддерживается усечением: собирается полный
58-вектор, но используются первые 52 значения
([`nnue.rs:296-298`](../engine/src/nnue.rs#L296-L298)).

## Прямой проход

[`evaluate()`, nnue.rs:292](../engine/src/nnue.rs#L292)

```rust
// Слой: acc = bias × SCALE + Σ(weight × input); затем /SCALE и clamp
for j in 0..h1 {
    let mut acc = self.fc1_bias[j] as i32 * SCALE;
    let w = &self.fc1_weight[j * in_sz..j * in_sz + in_sz];
    for i in 0..in_sz {
        acc += w[i] as i32 * input[i] as i32;
    }
    hidden1_buf[j] = (acc / SCALE).clamp(0, SCALE);
}
```

Аккумуляторы — `i32`, буферы фиксированного размера на стеке
(`[i32; MAX_HIDDEN1]`), без единой аллокации. Выходной слой не проходит через
CReLU — результат может быть любого знака.

SIMD-оптимизаций нет: код полагается на автовекторизацию LLVM при `opt-level = 3`.

## Копии для многопоточности

Каждый воркер Lazy SMP получает **свою копию сети** через `nnue.clone()`
([`search.rs:279`](../engine/src/search.rs#L279)). При 8 потоках это 8 копий
весов в памяти. Для 37 КБ это несущественно, но при более крупной сети стоило бы
перейти на `Arc` — как это уже сделано для EGTB.

## Обучение

Скрипты обучения лежат в `engine/`, основной —
[`train_custom_k.py`](../engine/train_custom_k.py). Полное описание пайплайна:
[11-data-and-training.md](11-data-and-training.md).

Ключевой параметр — `K` в сигмоиде, преобразующей оценку в вероятность победы.
Исправление `K = 1050 → K = 400` дало **+256 Elo** — крупнейший единичный
прирост за всю историю проекта.

Веса дополнительно сохраняются в JSON
([`nnue_weights.json`](../engine/nnue_weights.json), 424 КБ) — удобно для
инспекции и диффов, но в движке не используется.
