# 08. CLI и протокол `serve`

Файл: [`engine/src/main.rs`](../engine/src/main.rs) (845 строк)

Все команды запускаются **из директории `engine/`** после сборки — движок ищет
веса, книгу и таблицы по относительным путям (см.
[03-build-and-run.md](03-build-and-run.md#важно-рабочая-директория)).

```bash
cd engine
./target/release/togyzkumalaq-engine <команда> [аргументы]
```

| Команда | Назначение |

## Подробности по командам

### `play`

[`play_interactive`, main.rs:157](../engine/src/main.rs#L157)

Загружает NNUE, EGTB и книгу, играет против человека, использует все ядра.
История ходов сохраняется — доступен откат
([`main.rs:235-237`](../engine/src/main.rs#L235-L237)).

### `perft`

Классический тест из шахматного мира: подсчёт числа листьев дерева на заданной
глубине. Единственный автоматический способ проверить, что генератор ходов и
правила не сломаны. Референсные значения — в
[`validate_perft.py`](../validate_perft.py).

### `analyze`

```bash
./target/release/togyzkumalaq-engine analyze "9,9,9,9,9,9,9,9,9/9,9,9,9,9,9,9,9,9/0,0/-1,-1/0" 3000
```

Формат позиции описан в [02-game-rules.md](02-game-rules.md#формат-позиции).

### `selfplay`

[`run_selfplay`, main.rs:357](../engine/src/main.rs#L357)

Партия движка с самим собой: 1000 мс на ход, максимум 20 плай. Загружает
только NNUE — **без EGTB и без книги**, поэтому результат не отражает полную
силу движка.

### `datagen`

```bash
./target/release/togyzkumalaq-engine datagen 10000 8 4 local
```

Аргументы: число партий, глубина поиска, число потоков, префикс выходных файлов.
Подробности формата — [11-data-and-training.md](11-data-and-training.md).

# Протокол `serve`

[`run_serve`, main.rs:660](../engine/src/main.rs#L660)

Режим постоянного процесса: движок читает команды из stdin и отвечает **одной
строкой** в stdout. Придуман для веб-сервера, чтобы между ходами сохранялись
таблица транспозиций и история партии.

## Разделение потоков

| Поток | Содержимое |
|-------|-----------|
| **stdout** | только ответы протокола, по одной строке |
| **stderr** | диагностика: `info depth ...`, сообщения о загрузке весов |

Это разделение критично: клиент читает ровно одну строку из stdout на команду
([`server.py:66`](../web/server.py#L66)). Если бы строки `info` шли в stdout,
протокол бы рассинхронизировался.

## Рукопожатие

При старте движок загружает NNUE, EGTB и книгу (сообщения — в stderr) и пишет:

```
ready
```

Клиент обязан дождаться этой строки перед первой командой
([`server.py:39-41`](../web/server.py#L39-L41)).

## Команды

### `newgame`

Сбрасывает состояние поиска: TT, эвристики, история партии.

```
→ newgame
← ready
```

### `position <позиция>`

Добавляет позицию в историю партии для детекта повторений. Клиент вызывает это
после **каждого хода человека** — иначе движок не увидит повторение.

```
→ position 9,9,9,9,9,9,9,9,9/9,9,9,9,9,9,9,9,9/0,0/-1,-1/0
← ready
```

### `go time <мс> pos <позиция>`

Основная команда — поиск лучшего хода.

```
→ go time 3000 pos 11,11,0,12,12,12,2,11,11/11,11,11,11,11,11,11,11,11/0,10/-1,-1/1
← bestmove 6 score 142 depth 24 nodes 8451203 time 3012 nps 2807203
```

Поля ответа:

| Поле | Смысл |
|------|-------|
| `bestmove` | индекс лунки **0..8** (в интерфейсе показывается +1) |
| `score` | оценка с точки зрения ходящего |
| `depth` | достигнутая глубина |
| `nodes` | просмотрено узлов |
| `time` | фактически потрачено мс |
| `nps` | узлов в секунду |

Поиск ограничен глубиной 30 и использует все ядра
([`main.rs:758`](../engine/src/main.rs#L758)).

Если переданная позиция терминальна, вместо хода приходит:

```
← terminal white_win
```

Возможные значения: `white_win`, `black_win`, `draw`, `unknown`.

**Побочный эффект**: после поиска движок сам применяет найденный ход и добавляет
получившуюся позицию в историю ([`main.rs:760-764`](../engine/src/main.rs#L760-L764)).
Клиенту не нужно отдельно вызывать `position` после хода движка — только после
хода человека.

### `ping`

```
→ ping
← pong
```

Проверка живости процесса.

### `quit`

Завершает процесс. Ответа нет.

### Неизвестная команда

```
← error unknown command: <строка>
```

Ошибка разбора позиции:

```
← error Expected 5 parts separated by '/', got 3
```

## Полный пример сессии

```
                                    ← ready                        (после старта)
→ newgame                           ← ready
→ position 9,9,...,9/9,...,9/0,0/-1,-1/0
                                    ← ready
→ go time 3000 pos 9,9,...,9/9,...,9/0,0/-1,-1/0
                                    ← bestmove 6 score 12 depth 26 nodes 9123456 time 3001 nps 3040138
→ position <позиция после хода человека>
                                    ← ready
→ go time 3000 pos <та же позиция>
                                    ← bestmove 4 score 31 depth 25 ...
→ quit
```

## Реализация клиента

[`web/server.py`](../web/server.py) — эталонная реализация:

```python
def send_command(cmd):
    if engine_proc is None or engine_proc.poll() is not None:
        start_engine()                       # автоперезапуск при падении
    engine_proc.stdin.write(cmd + '\n')
    engine_proc.stdin.flush()
    return engine_proc.stdout.readline().strip()
```

Существенные детали:

- Процесс запускается с `bufsize=1` (построчная буферизация) и `text=True`.
- Все обращения сериализованы через `threading.Lock` — протокол
  однопоточный, параллельные команды его сломают.
- `cwd=ENGINE_DIR` — иначе движок не найдёт свои файлы.
- Корректное завершение через `atexit` с отправкой `quit` и `wait(timeout=5)`,
  затем `kill()` ([`server.py:45-55`](../web/server.py#L45-L55)).
